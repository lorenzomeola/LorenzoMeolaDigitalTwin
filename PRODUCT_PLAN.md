# Personal Digital CV - Product Plan

## Product Vision

Build a personal website that helps hiring teams understand Lorenzo Meola's engineering background, evaluate his transition into AI Engineering, inspect real project evidence, and ask his Digital Twin focused questions. Present learning honestly alongside professional experience; do not imply seniority or outcomes that have not been demonstrated.

## Audience

- Hiring managers and recruiters assessing Lorenzo for AI Engineer roles.
- Engineering teams interested in his software, data, and applied AI work.

The initial site is a job-search portfolio, not a services marketplace or general-purpose personal blog.

## Information Architecture

- **About (`/`)**: concise professional introduction, current focus, and routes to the CV, projects, and chat.
- **Resume (`/resume`)**: education, experience, skills, and downloadable PDF CV.
- **Projects (`/projects`)**: project cards with ownership, status, contribution, technology, evidence, and public links.
- **Digital Twin (`/chat`)**: direct route to the AI conversation. The same chat opens as a full-screen overlay from the other pages and closes back to the previous page.

## MVP Scope

### Website

- Responsive Next.js site with shared navigation and a coherent visual system inspired by the supplied portfolio references.
- About, Resume, and Projects routes.
- Full-screen Digital Twin chat overlay, direct `/chat` route, suggested questions, message input, loading state, error state, and accessible close control.
- Downloadable CV and verified links to GitHub and project demos/repositories.
- Static structured content for profile and project facts so updates do not require redesigning the site.

### Projects in the First Release

1. **CCA Fleet Analytics & Predictive Maintenance** - ongoing Volvo Group work. Describe the analytical backend, REST API, alert simulation and optimization, and exploratory classifiers. Do not expose real Volvo data, screenshots, or internal links. Use synthetic data for any public demonstration. Claim no unvalidated model performance, reduced breakdowns, or savings.
2. **AI Assets Directory** - live and actively maintained directory. The supplied snapshot listed 170 entries. Describe verified product capabilities and stack, but do not claim Lorenzo's exact role until he confirms it. Date the listing count or derive it dynamically if shown.

## Digital Twin Behavior

- Identify itself as Lorenzo's AI Digital Twin when asked; never pretend to be Lorenzo himself.
- Answer career, skills, education, and project questions using only the verified profile, CV, and project records.
- Distinguish professional employment, personal projects, and coursework.
- State uncertainty rather than inventing details, ownership, metrics, availability, or results.
- Keep answers useful to employers and focused on evidence of engineering ability.
- Save contact details only after the visitor supplies an email and explicitly confirms storage through a visible consent control. The model cannot grant consent on the visitor's behalf. Unknown questions are not stored.

## Contact and Privacy

- Store contact requests in a dedicated Neon Postgres database for the MVP, separate from MatchKeeper. Keep the schema portable so it can move to Supabase Pro later.
- Require explicit consent from a visible UI control before the backend calls the storage tool; record when consent was given. Do not trust a consent flag generated by the model.
- Keep the Neon database URL and OpenAI key on the server only.
- Do not create visitor accounts or persist conversation history in the MVP.
- Never place confidential Volvo information in content, logs, tests, or demo data.

## Success Criteria

- A visitor can reach About, Resume, Projects, and the Digital Twin from desktop and mobile.
- The chat can answer a representative question about each of the three projects without contradicting the supplied status and evidence rules.
- The visitor can open and close the full-screen chat without losing the current site route.
- Contact data is stored only after explicit consent; requests without consent are rejected.
- The portfolio remains browseable if the chat API is unavailable.
- The site builds and deploys with no secrets in the browser bundle.

These are release criteria, not claims of hiring outcomes, traffic, or business impact.

## Delivery Phases

1. **Foundation**: create the monorepo structure, preserve the Gradio prototype, centralize profile/project content, and document setup.
2. **Portfolio shell**: scaffold Next.js, add shared navigation and the About, Resume, and Projects routes using verified content.
3. **Twin API**: create the FastAPI chat endpoint, port prompt/tool behavior, validate requests, and connect consent-gated contact storage to the dedicated Neon Postgres table.
4. **Chat experience**: build the full-screen overlay and direct chat route; connect it to the API and cover loading, failure, and mobile states.
5. **Release**: run functional, privacy, and build checks; deploy the frontend to Vercel and the Python API to a selected Python-capable host; configure production environment variables and verify the live site.
6. **Ongoing portfolio updates**: add a project or course milestone only when there is a concrete artifact, clear personal contribution, and honest status/evidence.

## Out of Scope for MVP

- Separate websites or repositories for each page.
- A services catalog, payments, subscriptions, bookings, or visitor accounts.
- Chat transcript persistence, RAG, multi-agent orchestration, or unrelated tools.
- Public Volvo screenshots, production data, or internal system links.
- Claims of real-money MatchKeeper payments, adoption, or quantified impact without validation.
